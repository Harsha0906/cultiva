# Step 1.3: App shell & navigation

## Goal
A running app with the approved navigation structure, so every later feature has a place to live.

## Design (from [01-design-spec.md](../01-design-spec.md) §1)
- **Bottom nav, 4 tabs:** Farm `/farm`, Tasks `/tasks`, Shop `/shop`, Progress `/progress`.
  - Built with go_router `StatefulShellRoute.indexedStack`, so each tab keeps its own back history and scroll state.
- **Top-level routes** (above the shell, with no bottom nav):
  - `/profile`: opened from the header avatar.
  - `/focus/:taskId`: Focus Mode. The `taskId` is validated, and an invalid id shows a "Task not found" state with a way back.
- **Calendar button** → `/progress?view=calendar`. The Progress tab reads `view` to scroll to the calendar.
- **Farm header placeholder:** avatar button, coins/progress pill, calendar button, each with a 44pt tap area and an accessible label.
- **Unknown route** → error screen with a "Back to farm" button.
- **Theme:** colour tokens from the design spec (teal, terracotta, wood, paper, ink). The real pixel UI kit replaces the placeholders in step 2.3, and the nav uses Material icons until then.

## Implementation plan
1. `core/theme/tokens.dart` and `core/theme/app_theme.dart`.
2. `core/router.dart` with typed route constants (`Routes.farm` etc.) and the `focusPath(id)` builder.
3. `features/shell/app_shell.dart`: `NavigationBar` with icons and labels. Re-tapping the active tab returns it to its root.
4. Placeholder screens: farm (with header), tasks, shop, progress, profile, focus, not-found.
5. `app.dart` (`MaterialApp.router`) and `main.dart` (`ProviderScope`).
6. Widget tests:
   - switching tabs keeps each tab's state
   - the calendar button opens Progress with the calendar view
   - Profile push and pop
   - an invalid focus id shows "not found"
7. Run on the `cultiva_pixel` emulator and take a screenshot.
