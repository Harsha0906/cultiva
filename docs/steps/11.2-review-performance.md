# Step 11.2: Code review and performance pass

## Code review (flutter-code-review checklist)
- **Correctness:** async gaps (`mounted` checks after `await`), stream and controller disposal, timers cancelled, farm-day maths at the reset hour, and coin ledger invariants (daily cap, no double pay).
- **State:** providers that rebuild too much; `liveQuery` subscriptions closed with their provider.
- **Data:** every multi-row write inside a transaction; indexes for the hot queries (completions by day, ledger by day/refId).
- **Platform:** notification ids that don't collide; permission flows; the release build's R8 rules for the plugins.
- **Hygiene:** no debug-only code reachable in release (the `/dev` route is behind `kDebugMode`), no leftover TODOs that matter, and the `pubspec` description.

## Performance
- **The Flame farm scene** must not burn CPU while the farm tab is hidden or the app is in the background (pause the engine), and must stay calm when nothing animates.
- **Frame timing:** a profile build on the emulator with `flutter run --profile` and the frame stats from `adb shell dumpsys gfxinfo com.cultiva.app` while scrolling Progress and using the farm. Emulator numbers are a guide only; real-phone numbers are better.
- **App size:** `flutter build apk --release --analyze-size --target-platform android-arm64`. Look for big assets and unused packages (`cupertino_icons` and `riverpod_annotation` are unused, so remove them).
