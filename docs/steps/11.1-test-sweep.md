# Step 11.1: Test sweep

## Goal
Make sure the main flows are covered end to end on a real Android runtime, not just in widget tests, and find any important code with no tests.

## Plan
1. **Coverage report:** `flutter test --coverage`, then list per-file line coverage for `lib/` (generated `db.g.dart` excluded). Files under ~60 % that hold logic (services, domain, notifications) get targeted tests. Pure layout files are judged case by case.
2. **Integration test** (`integration_test/app_flow_test.dart`, Flutter's SDK `integration_test` package) runs on the emulator with an in-memory database:
   - **First launch:** onboarding → name → avatar → task → (short) breathing → harvest → +20 coins → "Not now" → farm.
   - **To-do loop:** plant a to-do from Tasks → Done → Harvest → coin balance goes up.
   - **Shop:** buy an affordable decoration → it appears in the barn storage.
   - **Progress:** today shows the completions.
   - **Profile:** rename → the name shows.
3. **Regression list:** confirm the bugs fixed in Phases 1–10 each have a test (rollover auto-harvest, the focus clock guard, the full-basket bonus, liveQuery coalescing, the rename dialog crash, onboarding gift paid once).

## Verification
`flutter test` (all unit and widget) plus `flutter test integration_test -d emulator-5554` both green.

## Skills
flutter-testing, flutter-device-testing

## What was built
2026-11-15:
- **Coverage:** **74.4 % → 76.3 %** line coverage of `lib/` (60 files, generated code excluded).
  - Still low, on purpose: `farm_game.dart` (the Flame scene; now exercised on the device by the integration test), `kit_gallery_screen.dart` (debug only), `db.dart` (connection setup) and `LocalNotifier` (platform plugin; verified on the emulator in Phases 6 and 9).
- **New unit tests** (`test/data/repositories_test.dart`):
  - Task edit saves trimmed fields; an empty title is rejected and the old one kept.
  - Restore moves to a free slot when the old one was taken, and throws when the plot is full.
  - The journal keeps omitted fields, `clearMood` keeps the note, and a mood of 6 is rejected.
- **New widget test:** the barn spot picker places a decoration, swaps out the occupant and takes it back (it had 0 % coverage).
- **Removed** the unused `TaskRepository.rename`, which skipped title validation.
- **Integration test** `integration_test/app_flow_test.dart` passes on emulator-5554 (about 65 s) with the real Flame scene, real audio and a fresh database:
  - onboarding → +20 coins → farm "Next up: Meditate"
  - plant a to-do → Done → Harvest → balance goes up
  - buy a decoration → it's owned
  - Progress logs today
  - rename in Profile
- **Bug found by the integration test:** audioplayers' default position updater requested a new frame every vsync after the first sound, because low-latency mode never reports completion, so the app could never idle (a battery drain). Fixed: `positionUpdater = null` on every SFX player.
- **Regression list confirmed:** rollover auto-harvest, the clock guard, the full-basket bonus, liveQuery coalescing, rename, the gift paid once, and "I already did it" all have tests.
- **146 unit and widget tests, plus 1 integration test, pass.**
