# Step 2.3: Pixel UI kit, fonts & theme

## Goal
Replace the stock Material look with Cultiva's own pixel UI vocabulary, so every later screen is built from the same parts.

## Design signature
| Aspect | Choice |
|---|---|
| Background | Warm paper `#F8EED6`; the farm scene sits behind the Farm tab |
| Surfaces | **Kraft-paper 9-slice panels** with a wood outline and a dashed stitch. A **wood panel** variant is used for the nav bar and signs |
| Actions | **Pixel buttons** with a 3D lip that shifts down 2 px when pressed. Variants: `primary` (terracotta, the screen's one main action), `teal` (secondary), `wood` (neutral), `paper` (quiet) |
| Type | **Pixelify Sans** for headings, numbers, buttons and labels. **Nunito** for task names and body text, so it stays readable and scales with system text size |
| Icons | 16×16 **single-colour pixel silhouettes**, tinted in code (`BlendMode.srcIn`), shown at 2× (32 dp) inside 48 dp tap areas |
| Pixel scale | UI art draws at **2 dp per art pixel**, with `FilterQuality.none` |

## Parts
- **Images:** `app/assets/ui/` (drawn by `tools/art/draw_ui_kit.py`):
  - `panel_paper.png`, `panel_wood.png`: 24×24, 9-slice centre 8,8,8,8
  - `btn_{primary,teal,wood,paper}.png` and `btn_*_pressed.png`: 24×24 9-slice
  - `icons/{farm,tasks,shop,progress,calendar,plus,play,check,timer,gear,lock,close,back}.png`: 16×16 white silhouettes
- **Fonts:** `app/assets/fonts/` holds `PixelifySans[wght].ttf` and `Nunito[wght].ttf`, both from the google/fonts repo under the OFL license. The license texts are kept beside them.
- **Flutter:**
  - `core/theme/text.dart`: TextTheme with pixel display/title/label roles and Nunito body roles
  - `core/ui/pixel_panel.dart`: `PixelPanel` (paper or wood)
  - `core/ui/pixel_button.dart`: `PixelButton`, which handles variant, pressed and disabled states, a loading state that blocks double taps, semantics and a 48 dp minimum
  - `core/ui/pixel_icon.dart`: `PixelIcon` (tinted, integer-scaled)
  - `features/shell/app_shell.dart`: the nav becomes a **wood panel bar with pixel icons and labels**. The active tab is shown by a terracotta tile plus a bold label, so colour isn't the only signal
  - A debug-only **`/dev/kit` gallery** renders every part in every state, for visual checks on the emulator

## States covered
Button: normal, pressed, disabled (40% opacity, no tap), loading (spinner text, taps blocked), long label (wraps to 2 lines). Panel: short and long content.

## How we verify it
- Widget tests: button pressed/disabled/loading behaviour, semantics labels, nav selection.
- Emulator screenshots of the kit gallery and the Farm screen with the new nav. Check contrast for teal on paper, white on terracotta, and cream on wood.

## Skills
flutter-ui-design, ui-ux-pro-max, flutter-accessibility

## What was built
2026-11-15:
- **Kit images** are drawn by `tools/art/draw_ui_kit.py` into `app/assets/ui/` (committed): 2 panels, 4 buttons × 2 states, 13 icons. The farm icon is a hand-drawn sprout map.
- **Fonts:**
  - `assets/fonts/PixelifySans.ttf` and `Nunito.ttf`, downloaded from the google/fonts repo with the OFL text beside each.
  - The `[wght]` part of the file names was dropped because PowerShell treats square brackets as wildcards.
- **Widgets:** `PixelPanel`, `PixelButton` (variants, pressed lip shift, disabled, loading, wraps to 2 lines), `PixelIconButton`, `PixelIcon`, `PixelNavBar`, `buildTextTheme()`.
  - The Farm header now uses pixel buttons, a coin sprite and the calendar date.
  - The avatar slot is a placeholder until step 2.4.
- **Debug route** `/dev/kit` with a gallery of every state, available in debug builds only.
- **Issues found on device and fixed:**
  1. **9-slice middles stretch in Flutter**, so dashed stitches turned into bars and wood planks into one stripe. The panel middles now have no pattern: a solid inset stitch line, and a highlight line on wood.
  2. **Buttons without an icon were shorter**, so a minimum content height of 16 art px was added.
  3. **Icons drew at 16 dp instead of 32**, because `Image`'s default fit is `scaleDown` and never enlarges. It's now `BoxFit.fill`, and a regression test checks the size.
- **Tests:** 10 pass:
  - button tap, disabled and loading
  - 48 dp minimum and semantics label
  - icon size 32 dp
  - nav selected state for screen readers
  - the navigation suite
- **Screenshots:** `docs/design/screens/phase2-kit.png`.
