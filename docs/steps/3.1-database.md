# Step 3.1: Database & repositories (Drift)

## Goal
Durable, offline-only storage for everything the player creates, kept behind repositories so screens never touch SQL.

## Data classification (per the flutter-persistence skill)
- **All tables below are durable user data.**
- **A migration must never wipe them**, not even on failure; the app surfaces the error instead.
- Derived numbers (coin balance, stats) are **computed by queries**, not stored.

## Schema v1 (`app/lib/data/db.dart`)
| Table | Columns |
|---|---|
| `tasks` | id (uuid, PK), title, plot (`daily`/`todo`), kind (`timed`/`check`), targetMinutes?, repeatMask (int, Mon=bit0; 0 = to-do), crop, slot (0–5), createdDay, createdAt, archivedAt? |
| `completions` | id (uuid), taskId → tasks, day, method (`focus`/`manual`/`check`), minutes, ripenedAt, harvestedAt?, coins (paid at harvest, incl. any bonus share). Unique (taskId, day) |
| `focus_sessions` | id, taskId, day, startedAt, plannedSec, accumulatedSec, status (`running`/`paused`/`done`/`abandoned`), suspicious (bool), endedAt? *(used in Phase 6)* |
| `journal` | day (PK), mood (1–5)?, note?, updatedAt |
| `inventory` | itemId (PK), qty, placedSpot? *(Phase 7)* |
| `coin_ledger` | id (autoinc), delta, reason, refId?, day, createdAt. **Append-only** |
| `settings` | key (PK), value (text) |

Indexes: `completions(day)`, `coin_ledger(day)`, `focus_sessions(taskId, day)`.

## Repositories (`app/lib/data/`)
- `TaskRepository`: `watchActive()`, `plant()` (slot from the engine; refuses a 7th), `archive()`, `byId()`
- `CompletionRepository`: `watchDay(day)`, `ripen()`, `harvest()`, `unharvest()`, `lastHarvestDays(taskId)`
- `LedgerRepository`: `watchBalance()`, `earnedOn(day)`, `append()`
- `SettingsRepository`: typed getters and setters (reset hour, avatar id, farmer name, …) with defaults
- `JournalRepository`: `watch(day)`, `upsert()`

## Wiring
- `drift_flutter` `driftDatabase(name: 'cultiva')` on device.
- Tests use `NativeDatabase.memory()`.
- Riverpod providers in `app/lib/data/providers.dart`.

## Migrations
`schemaVersion = 1`. The schema is exported with `drift_dev schema dump` to `app/drift_schemas/`, so future versions can be tested against the real v1 schema.

## Verification
Repository tests on an in-memory DB:
- planting fills slots and refuses a 7th
- the unique completion per task per day
- ledger balance is the sum of rows
- settings defaults and round-trips
- journal upsert
- reopening a file DB keeps the data

flutter-persistence, flutter-testing

## What was built
2026-11-15:
- **`data/db.dart`** has schema v1 with 7 tables and 3 indexes. Foreign keys are on. The generated `db.g.dart` is committed, so a build doesn't need build_runner.
- **Repositories:**
  - `TaskRepository`: plant, archive, restore, rename, watch
  - `ProgressRepository`: completions plus the append-only ledger, balance, earned-today, Full Basket flag
  - `SettingsRepository`: typed values with validated defaults
  - `JournalRepository`
- **`FarmService`** connects the engines to storage:
  - `today()`, `plants()` (each with its stage), `complete`, `harvest`, `unharvest`, `uncomplete`
  - Harvest and unharvest run in transactions.
  - Ledger rows carry the completion id, so an undo reverses exactly what was paid, bonus included.
- **`data/providers.dart`:** Riverpod `dbProvider`, `clockProvider` (test seam), `farmServiceProvider`, `journalRepositoryProvider`.
- **Schema snapshot** at `app/drift_schemas/drift_schema_v1.json`, for migration tests when v2 arrives.
- **17 database and service tests** on in-memory SQLite:
  - slot filling and 7th refused; invalid tasks; archive frees a slot
  - harvest pays tier coins; no double harvest; manual half rate
  - Full Basket once; cap at 150
  - a to-do leaves the plot and undo restores it; unharvest reverses the bonus
  - dormant → revive; done yesterday → seed today; 2 am counts as yesterday; custom reset hour
  - settings and journal round-trips; a **file database survives close and reopen**
- **Totals:** 61 tests pass, the analyzer reports no issues, and the Android debug build compiles with SQLite.
- **Not wired to the UI yet.** The screens start reading `farmServiceProvider` in Phase 4 (farm) and Phase 5 (tasks).
